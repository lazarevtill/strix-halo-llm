# Layout — where every part lives, and how to add new ones

Since 2026-10-16 the serving system has one layout. **One file knows it:**
[`scripts/windows/paths.ps1`](../scripts/windows/paths.ps1). Every script dot-sources it instead of
hardcoding a path. **One command checks it:** [`scripts/windows/check-layout.ps1`](../scripts/windows/check-layout.ps1)
verifies that every engine, model and launcher reference resolves, and writes the index `models\INDEX.md`.

```
<checkout>\                         (D:\llamacpp-vulkan on the reference box)
├── scripts\windows\                 tracked: launchers, fetchers, benches  -- all use paths.ps1
├── evals\                           tracked: the eval harness (private cases are gitignored)
├── docs\                            tracked: results, guides, this file
│
├── engines\                         gitignored: every serving binary, one folder per build
│   ├── llama.cpp\<build>\            b10431 (the pin for published numbers), b11414 (live), ...
│   ├── stable-diffusion.cpp\<build>\ master-967-e47426c, master-968-8cd731e (image/video server)
│   ├── poolside\                     poolside's llama.cpp fork (build-poolside.ps1)
│   └── _attic\                       parked duplicates -- check-layout lists them, safe to delete
├── models\                          gitignored: all weights
│   ├── llm\                          LLM GGUFs + their draft models (mtp-*, *-DFlash-*) + mmproj files
│   ├── image\                        image / video weights, text encoders, VAEs
│   │   ├── loras\  upscalers\  detectors\  embeddings\
│   │   └── image-models.local.json   models added from Hugging Face / CivitAI (never tracked)
│   └── INDEX.md                      generated by check-layout.ps1: every file, size, and what uses it
├── logs\                            gitignored
│   ├── llm\  images\  bench\  downloads\
│   └── layout-migration-*.tsv        the 2026-10-16 moves (from -> to), for undoing them
├── outputs\                         gitignored: generated images\ edits\ videos\ (one folder per day)
└── private\                         gitignored: the image/video server -- a separate, private repo
```

Outside the checkout, one thing: the **Startup launcher**
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\StrixHalo-Router.cmd`, which decides what
`:8080` serves at logon. It is not in any repo, so `check-layout.ps1` reads it and checks every script and
engine it starts.

## The rules

1. **Never hardcode a path.** In a script: `. (Join-Path $PSScriptRoot 'paths.ps1')`. The resolver provides:
   - `Get-StrixEngine b11414` → `engines\llama.cpp\b11414`. It also accepts `bin-b11414`,
     `.\bin-b11414`, `master-968-8cd731e`, `poolside` and full paths. `''` means the pinned b10431.
   - `Get-StrixModelsDir llm|image`, `Find-StrixModel <file name>`, `Get-StrixLogDir llm|images|bench|downloads|evals`.
   - `$StrixRoot` is the checkout.
2. **One build per folder, named by build.** Two copies of the same build are not kept. The duplicate
   goes to `_attic`.
3. **Weights by kind.** Anything a llama.cpp launcher loads goes in `models\llm`. Anything the image/video
   server loads goes in `models\image`. A file used by both does not exist today; if one appears, keep it
   in `models\llm` and reference it by full path.
4. **Old locations still resolve** (`bin\`, `bin-<build>\`, a flat `models\`, `C:\llm-router\models`), so
   an old checkout keeps working. `check-layout.ps1` reports them as WARN until they are moved.
5. **Overrides:** `$env:MODELS_DIR` (LLM weights) and `$env:IMAGE_MODELS_DIR` (image weights) point at
   folders elsewhere, e.g. on another drive.
6. **After any change, run `.\scripts\windows\check-layout.ps1`.** Exit code 1 means something a launcher
   needs is missing.

## How to …

### … add a new llama.cpp build

```powershell
.\scripts\windows\fetch-llamacpp.ps1 -Build b11500        # -> engines\llama.cpp\b11500
.\scripts\windows\stage-nextgen.ps1 -Bin b11500 -Model Ornith-1.5-35B-Q6_K.gguf -UBatch 1024   # determinism gate
.\scripts\windows\bench-big.ps1 -Bin b11500 -Only ornith15 -UBatch 1024                          # A/B vs the live build
```

The determinism gate is **per binary and per config** (see CLAUDE.md, #27805). Pass it before serving.
Then change `-Bin` in the Startup launcher (router **and** watchdog lines) and record the A/B with its
build, quant, context depth and ubatch (docs/BENCHMARKS.md rules).

### … add a new LLM

1. **Download** it into `models\llm`. Either add a label to `scripts\windows\fetch-models.ps1` (repo,
   files with exact byte counts from the HF tree API, a note) and run `fetch-models.ps1 -Only <label>`,
   or copy the GGUF there by hand.
2. **It is servable immediately:** `run-router.ps1` discovers every GGUF in `models\llm` and auto-tunes
   it. It reads the MTP head from the GGUF header and pairs an mmproj by sibling name.
3. **Gate it:** `stage-nextgen.ps1 -Bin <build> -Model <file>` (arch check, isolated load on :8099,
   12-run determinism diff).
4. **Measure it:** `bench-big.ps1` (depth-aware; never trust depth 0) and `bench-spec.ps1` if it has a
   speculator (sweep `-NMax` downward from 3).
5. **Pin its measured flags:** add a `$known` line to `run-router.ps1`. That covers `match`, `label`,
   the measured `spec` lines (ubatch, draft model as `@MODELS@\<file>`, `lazy-mode`, …) and `mmproj`,
   with the measurement in the comment.
6. `check-layout.ps1`, then document the numbers (docs/RESULTS.md / ROADMAP.md) with their context.

### … change what `:8080` serves

Edit the Startup launcher. Each mode is a block of `start` lines, and the inactive ones are kept as
`rem <MODE>-ROLLBACK:` lines:

- **LLM:** `run-router.ps1 -Models <label> -Bin <build> -Parallel N -PerSlotCtx <ctx>`, plus
  `metrics-exporter.ps1 -Port 9114` and `router-watchdog.ps1` with the **same** arguments.
- **Image/video server:** `private\run-images.ps1 -Port 8080`.

Only one mode can hold `:8080` and the GPU at a time. To switch without logging off:

1. Stop the running supervisor and its children: `powershell.exe` running run-router / run-images,
   `llama-server.exe`, the image server's `python.exe` and `sd-server.exe`.
2. Run `cmd /c "<Startup>\StrixHalo-Router.cmd"`.
3. Verify that `:8080` answers (`GET :8080/models` for the LLM; the image server's own check is in its
   private docs), then run `check-layout.ps1`.

### … add an image or video model (the published part)

The image/video server is private. Its **configuration** is public:

- Add a registry entry to [`scripts/windows/image-models.json`](../scripts/windows/image-models.json):
  `id`, `label`, `kind` (`image`/`video`), `family`, `licence`, `vram_gb` (measured), `compute_gb`,
  `files` (sd-server flag → file name in `models\image`), `args`, optional `engine` (a build under
  `engines/stable-diffusion.cpp/`), optional `default_lora`, and `ui` defaults.
- Add a download label to `fetch-models.ps1` with `dir = 'image'`, so its files land in `models\image`.
  A LoRA uses `as='loras\<file>'`.
- Fetch the files, run `check-layout.ps1` (every `files` value must exist), and publish only the
  **measured numbers** in [IMAGES.md](IMAGES.md).

### … add a script

Put it in `scripts\windows\`, begin it with `. (Join-Path $PSScriptRoot 'paths.ps1')`, and take engines
as `-Bin <build>` and models by file name (`Find-StrixModel`). It must work under Windows PowerShell 5.1:
no `&&`, no ternary, no `??`. CI parses every `.ps1`. Add one line to [scripts/README.md](../scripts/README.md).

### … move weights to another drive

Move `models\llm` (or `models\image`) and set `MODELS_DIR` / `IMAGE_MODELS_DIR` with `setx`. Every script
and the image server honour them. Then run `check-layout.ps1`.

### … undo the 2026-10-16 move

`logs\layout-migration-<timestamp>.tsv` lists every `from<TAB>to` pair. Move each `to` back to its
`from`, newest first. The old locations still resolve, so nothing else has to change.
